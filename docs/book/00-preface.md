# ArkPeak: A Companion Book

### Building a cozy procedural town, from first principles

---

## About this book

This is a companion to the ArkPeak source code. It is written for two people
at once:

- **Someone who has never written a procedural generator.** You will learn
  what Wave Function Collapse actually is, why it works, and what happens
  when it breaks.
- **Someone who has never touched Go or Wails.** You will learn how a Go
  program can drive a web page as if it were a desktop application.

You do not need to read it in order, but it is written in order. If you are
new to all of it, read Chapters 1 through 4 in order and then skim the
rest. If you are here for one specific thing, the chapter list below will
send you straight there.

### How the code is laid out

Every chapter refers to real files. The paths are relative to the repository
root.

| Path | What lives there |
|---|---|
| `internal/wfc/` | The solver. Pure Go, no rendering, no Wails. |
| `internal/town/` | The town: authoritative state, ruleset, save/load, the service the frontend calls. |
| `internal/town/rules/town_rules.json` | The tile rules, as data. |
| `frontend/src/game/geometry/` | The renderer: grid maths, neighbour rules, procedural buildings. |
| `frontend/src/game/` | The state mirror, the camera, the input. |
| `frontend/src/ui/` | The palette and the HUD. |
| `build/` | Everything the platform packagers need. |

### A note on attribution

Townscaper was made by **Oskar Stålberg**. This project is not Townscaper and
is not endorsed by him. It is a study of the same ideas, built from scratch
as a teaching exercise.

Where this book quotes or paraphrases Oskar or the WFC literature, it says
so. Where it describes ArkPeak's own code, it says that too. Keeping those
two apart matters: some of the things ArkPeak does are faithful to the
original ideas, and some are simplifications or deliberate departures that
are worth understanding precisely because they differ.

## The short version

If you read nothing else:

1. **Townscaper is not a city builder.** There is no economy, no goal, no
   fail state. You place coloured blocks on a grid and the town *arranges
   itself* around them. The pleasure is in the arranging.

2. **The town is generated by Wave Function Collapse (WFC).** Every cell
   starts knowing every tile it could be. One at a time, a cell is
   collapsed to a single tile, and the consequences ripple outward. The
   result always obeys the rules and almost never looks like a grid.

3. **The rules are data, not code.** `town_rules.json` says "a wall meets a
   wall" and "a roof needs a wall underneath". The solver knows nothing
   about walls or roofs. Change the JSON and the town changes.

4. **ArkPeak puts the solver in Go and the picture in TypeScript.** Wails
   is the glue: the Go side owns the truth, the browser side draws it, and
   a generated binding carries messages between them.

5. **The interesting bugs are the interesting part.** A solver that
   *nearly* keeps the neighbourhood stable is worse than no solver at all,
   because the town slowly rewrites itself while you are not looking.

## Contents

### Part I — The original game

**Chapter 1 — Townscaper: the game that is not a game**
What Oskar Stålberg made, what it is actually doing, and why it became a
touchstone for procedural generation.

**Chapter 2 — Before Wave Function Collapse**
Oskar's own experiments: *Island* (2013), *CityGenerator* (2014) and
*Polygonal Planet* (2015). Understanding where the ideas came from makes
the algorithm much less mysterious.

### Part II — The algorithm

**Chapter 3 — Wave Function Collapse from the ground up**
Quantum-flavored names, the actual mechanics, and a complete worked example
you can follow with a pencil.

**Chapter 4 — Entropy, and why the algorithm feels like drawing**
The heart of the thing. Why the solver picks the *most constrained* cell
first, and why that is exactly what a human illustrator does.

**Chapter 5 — Propagation, and the rules that make a town**
How one choice constrains its neighbours, and how "wall", "roof" and
"edge" become a language for building.

### Part III — Building it

**Chapter 6 — ArkPeak's architecture**
The three-layer split — solver, town, renderer — and why the rules never
appear in TypeScript.

**Chapter 7 — Writing the solver in Go**
Bitmasks, the observation/propagation loop, and determinism.

**Chapter 8 — Wails: a Go program with a web page inside**
How the two halves talk, what the generated bindings do, and why the
frontend is not allowed to decide anything.

**Chapter 9 — Drawing a town in Three.js**
The hex grid, neighbour-aware geometry, chunked rebuilding, and props.

### Part IV — Being careful

**Chapter 10 — The bugs worth learning from**
Five real bugs in this codebase, what each one taught, and how to spot
the same class of bug in your own work.

**Chapter 11 — Where to go next**
An honest map of what is not built yet, and the interesting problems
waiting in it.

## How to run the thing

You will want the code open beside you.

```sh
git clone https://github.com/incurl/arkpeak.git
cd arkpeak

npm install --prefix frontend     # frontend dependencies
task bindings                     # generate the TypeScript bindings
task dev                          # run it
```

Requirements: Go 1.26 or newer (the module declares `go 1.26.0`), Node 20
or newer, the Wails v3 CLI, and the Task runner
(<https://taskfile.dev>). The Wails CLI is installed with:

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0
```

On Linux you also need the Wails build dependencies:

```sh
sudo apt install libgtk-4-dev libwebkitgtk-6.0-dev build-essential
```

The bindings are generated, not checked in, because their contents depend
on your Go module path. `task dev` (which runs `wails3 dev`) regenerates
them on every start, so the explicit `task bindings` step is only needed
once.

The `Taskfile.yml` at the repository root is the entry point for
everything:

| Task | What it does |
|---|---|
| `task dev` | Runs the application in development mode, with hot reload |
| `task bindings` | Regenerates the TypeScript bindings from the Go services |
| `task build` | Builds the native binary for the current platform |
| `task test` | Runs the Go test suite |
| `task test:frontend` | Type-checks and lints the frontend |
| `task check` | Runs the Go tests, the frontend typecheck and the lint |
| `task package` | Packages a production build of the application |
| `task verify:package` | Checks that the build assets carry ArkPeak's identity |
| `task icon` | Redraws the application icon from the generating script |
